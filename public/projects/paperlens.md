論文 PDF を読みながら、**1 文ごとの対訳**と、訳・用語・数式・読解メモを **Markdown の保管庫（vault）** に残していく、ローカルファーストな論文リーダーです。

中央に原文の PDF、右のサイドバーに 1 文ずつの日本語訳を並べます。サイドバーの文と PDF 上の枠は双方向に連動していて、PDF の文を押すとその訳のカードへ、カードを押すと PDF のその位置へ移ります。全文の翻訳は **Claude を MCP 経由で呼び出して行う**ので、翻訳 API のキーも追加の費用もかかりません。

もともと別々に作っていた「1 文単位の対訳リーダー（LogiXiv）」と「読解ノートアプリ（旧 PaperLens）」を、1 つのアプリにまとめ直したものです。

## できること

- **1 文ごとの対訳**: GROBID で論文を文単位に分け、PDF 上の座標と結び付けて表示する
- **選んだ箇所の記録**: マーカー・訳・用語の解説・数式（LaTeX 化と説明）を残せる
- **読解ノート**: テンプレートから作った `note.md` に、要約や考察をそのまま書ける
- **単語帳と数式帳**: 全論文の用語と数式を 1 つの画面で横断して引ける
- **Claude からの操作**: MCP サーバーを通して、取り込み・翻訳・用語集の更新などを Claude Desktop / Claude Code から行える
- **デスクトップ版とブラウザ版**: 中身は同じローカルサーバーと画面で、Electron のウィンドウでもブラウザでも開ける

## なぜ「ローカルで動く OSS」にしたか

研究室や企業で読む論文には、まだ公開されていない原稿も含まれます。PDF を他人のサーバーに上げる SaaS 型では使ってもらえないので、**サーバーは `127.0.0.1` にしか bind せず、本文が端末の外に出る経路をコードから消しました**。Host と Origin も確かめて、別のサイトからの操作も断ります。

外に通信が出るのは、利用者が明示したとき（選んだ箇所を Claude の API で訳す、URL から論文を取り込む など）だけです。GROBID も、既定では CrossRef に問い合わせに行く設定を切り、未公開原稿のタイトルが外へ出ないようにしています。

## 保管庫

データベースは持たず、保管庫フォルダの普通のファイルにすべてを置きます。**アプリを捨ててもデータが読める**ことを優先していて、同じフォルダを Obsidian の保管庫としてそのまま開けます。

```
<保管庫>/
└── papers/<論文ID>/
    ├── paper.pdf               取り込んだ PDF
    ├── note.md                 読解ノート
    ├── paperlens.json          マーカー・用語・数式
    ├── sentences.json          1 文ずつの対訳
    └── sentences.status.json   解析の進み具合
```

## 設計で工夫したところ

- **再解析しても訳が消えない**: 原文を正規化したハッシュで訳を結び直す。行末で割れた `block-` + `sparse` と `block-sparse` を同じハッシュにすることで、あとから GROBID を入れて解析し直しても訳が外れない
- **画面と Claude が同時に書いても壊れない**: 注釈は丸ごと上書きせず、「追加・更新・削除」の操作として、書く直前に読み直した最新の状態に当てる
- **人が直した訳は機械が上書きしない**: 手で修正した訳には印を付けて保護する
- **黙って壊れない**: GROBID が無いときの簡易解析では、2 段組の左右が混ざったり本文が抜け落ちたりすることがある。読み順の崩れと本文の欠落をそれぞれ自動で検出し、画面と MCP の両方で申告する。「もっともらしい訳が付いているのに原文が欠けている」状態が一番危ないと考えたため
- **解析の品質を数字で確かめる**: 正解が分かっている論文風の PDF を生成して解析にかけ、本文の再現率と混入数を測るスクリプトを用意した（2 段組で再現率 100%・混入 0 件）

## 技術構成

| 領域 | 使っているもの |
|---|---|
| 画面 | React 19 / TypeScript / Vite / pdf.js / KaTeX |
| サーバー | Node.js（`127.0.0.1` のみで待ち受け）/ SSE で保管庫の変更を通知 |
| 文分割 | GROBID（Docker）/ 無いときは pdf.js による簡易解析（ワーカースレッド） |
| AI 連携 | MCP サーバー（stdio）/ Anthropic SDK |
| デスクトップ | Electron |
| 構成 | npm workspaces のモノレポ（`packages/core` は外部依存ゼロ） |
