Web アプリの脆弱性診断で行う **偵察・列挙 → 脆弱性調査 → トリアージ → 報告書** の一連の作業を、ローカルの **Markdown に 1 件 1 ファイル**で記録していく、自作の診断支援アプリです。

データベースは持たず、保存先のフォルダをそのまま Obsidian の保管庫として開けます。デスクトップ版（Electron）とブラウザ版があり、中身は同じローカルサーバーと画面です。**MBSD Cybersecurity Challenges 2026** の診断では、調査・記録・報告の基盤として最初から最後までこのアプリを使いました。

## 作った理由

チームには、脆弱性診断が初めてのメンバーと経験者が混ざっていました。経験者のノウハウが本人の頭の中だけにある状態だと、初めての人は「次に何をすればいいか」が分かりません。そこで、**経験者のやり方を「フェーズ」と「各フェーズで使うツールの手引き」としてアプリ側に形にする**ことにしました。

| | フェーズ | 完了の条件 |
|---|---|---|
| E0 | 事前準備 | スコープと RoE に書面の承認がある |
| E1 | 偵察・列挙 | 攻撃面の一覧がそろい、入力点を洗い出した |
| E2 | 脆弱性調査 | チェックリストの全項目が「検出有」か「検出無」になった |
| E3 | 検証・トリアージ | 全発見事項に再現手順・証跡・CVSS・修正案がそろった |
| E4 | 報告 | 経営層と技術者の両方に向けて書き分けた報告書を納品した |

ホーム画面には、記録されたデータから判定した各フェーズの進み具合と「次の一手」が出ます。迷ったらそこを見れば、標準的な流れに沿って調査を進められます。

## できること

- **偵察**: nmap・httpx・nuclei・subfinder・ffuf などの出力を貼り付けると、形式を判定して攻撃面（サーフェス）として取り込む。nuclei の自動検出は「下書き」として起票し、手で裏取りするまで報告書に載せない
- **調査**: OWASP WSTG v4.2 / Top 10:2025 に沿ったチェックリストと、ツールの実行ログを管理する
- **トリアージ**: 発見事項を個票として起票し、組み込みの CVSS v3.1 計算機（FIRST の仕様どおりに実装し、既知のベクタ 10 件で検算）でスコアと深刻度を決める
- **証跡**: スクリーンショットを発見事項ごとにまとめ、秘匿値を塗りつぶすマスキング機能と、Cookie・トークン・メールアドレスの伏せ字漏れの自動点検を備える
- **報告書**: 発見事項から報告書の表や章を自動で組み立て、HTML・印刷用 PDF・Word・Markdown で書き出せる
- **ツールの手引き**: 診断で使う 44 ツールの使いどころとコマンド例、7 つのユースケースを収録
- **実行ランナー（デスクトップ版）**: 許可したツールだけを、スコープ・書面の承認・診断期間と照らし合わせてから実行し、改ざん検知付きの監査ログを残す

## AI エージェントとの協働

SecOwl の操作は **MCP サーバーとして公開**していて（39 ツール）、Claude から診断対象の作成から報告書の生成までを呼び出せます。サーバーは保存先の Markdown を直接読み書きするので、アプリを起動していなくても動きます。

MBSD CC では、Claude が MCP 経由で SecOwl を操作して調査と記録を進め、自分はスコープの管理、結果の裏取り、深刻度の確定を担当する、という人と AI の役割分担で診断を進めました。サーバーからモデルには「自動検出をそのまま確定にしない」「証跡や本文に実際のトークンや個人情報を書かない」といった方針を渡しています。読み取りだけに絞って公開するモードも用意しました。

## 設計で気をつけたところ

- **診断のデータを外に出さない**: サーバーは `127.0.0.1` だけで待ち受け、DNS rebinding 対策として Host・Origin・`Sec-Fetch-Site` を確かめる。Markdown に書かれた外部ドメインの画像も読み込まない
- **調査データだけを Git で共有する**: アプリ本体と調査データを分け、データのフォルダだけを別のリポジトリとしてチームで共有できるようにした
- **色だけに頼らない**: 配色はデジタル庁デザインシステムのトークンだけで組み、コントラストと色覚の違いによる見分けやすさを生成時に自動で検査する。深刻度は色に加えて形と区分名でも示す

## 技術構成

| 領域 | 使っているもの |
|---|---|
| 画面 | React / Vite / デジタル庁デザインシステムのトークン |
| サーバー | Express（`127.0.0.1` のみ） |
| デスクトップ | Electron（GitHub Actions で macOS 用の .dmg を自動ビルド） |
| AI 連携 | MCP サーバー（stdio・39 ツール） |
| データ | Markdown（1 件 1 ファイル）+ JSON。DB は使わない |

*画面写真はすべて架空のデモデータです。*
